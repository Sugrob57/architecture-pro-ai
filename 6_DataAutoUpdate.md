# 6. Автоматическое ежедневное обновление базы знаний

## 1. Выбор источника данных

В качестве источника данных будет использоваться файловая директория `/data/knowledge-base/posts/`.
Предполагается, что файлы в данной директории изменяются, либо появляются автоматически, при наличии изменений.

> В теории, можно реализовать скрипт, который будет мониторить появление новых сообщений в телеграм-канале. Но, телеграм-канал, все-таки, является лишь примером данных для датасета, но не является источником данных компании QuantumForge Software. 

## 2. Cкрипт обновления индекса

Для реализации автообновления базы индексов разработан скрипт [/data/autoupdater/data_loader.py](/data/autoupdater/data_loader.py), который работает по алгоритму:
1. Сканирует файловую директорию, и находит в ней новые или изменённые документы.
2. Разбивает документы на чанки.
3. Генерирует эмбеддинги.
4. Обновляет векторную БД (добавляет новые вектора, удаляет устаревшие).
5. Логирует весь процесс (сколько обновил, сколько добавил...)

## 3. Автозапуск по времени

В данной практической работе, для автоматического запуска обновления можно обойтись самописным шедулером, который будет выступать отдельным процессом, периодически запускающим обновление.

Пример такого скрипта реализован в файле [/data/autoupdater/schedule_update.py](/data/autoupdater/schedule_update.py)

При наличии kubernetes-кластера рекомендуется:
1. Запускать такой скрипт как отдельный deployment (pod, container).
2. Все цифры обработанных файлов (успешных, неуспешных, обновленных, добавленных ...) - публиковать как prometeus-метрики.
3. Это позволит собирать такие метрики в общую базу метрик компании, и наблюдать за обновлением на графиках. А также настроить алерты на случай сбоев автообновления.
